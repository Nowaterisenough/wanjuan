# 同步

书架、书籍资料、阅读进度、分组、书源、RSS 源、订阅规则和排序共用字段增量同步。

## 何时同步

本机新增、删除、修改后自动记录变化，短时间内的连续修改合并处理。新增上传新对象，修改只上传变化字段，删除上传删除记录。未变化的书籍和规则不会重复上传。

启动、网络恢复、书架下拉和“立即同步”负责拉取上次成功应用之后的云端变更。下拉同时检查书源目录，只有真实章节变化才产生上传。阅读保存和其他修改走同一个流程，不再单独在阅读页打开、退出或定时器中上传整本书。

检查时间、最后打开时间、同位置重复保存的进度时间和临时错误等本机状态不算业务修改。离线或失败的编辑保存在本机；应用运行期间退避重试，重新启动、网络恢复或手动拉取成功后也会继续处理。

## 时间戳和冲突

每次完整应用一个云端变更块后，在本地数据库保存云端提交游标。游标不是手机的“当前时间”，所以设备时间不同不会直接造成漏同步。再次拉取只读取游标后的变更，不重新下载整库。

不同字段并发修改会合并；同字段按成功提交顺序解决。远端删除不会被旧的离线编辑复活，明确重新加入书架仍可新增。操作失败、缺片或数据损坏时不推进未完成块的游标。

## WebDAV

填写服务器地址、账号、密码和子目录。服务器需要支持强 ETag 和条件写入，以安全处理多设备同时修改。若服务器不支持，会提示错误，不会冒险覆盖其他设备的修改。

## GitHub 仓库

1. 建议创建专用私有仓库，可以是空仓库。
2. 创建 Fine-grained Token，仅授权此仓库，授予 Contents 读写权限。
3. 填写“所有者/仓库名”、Token、分支和子目录；分支留空使用默认分支。
4. 所有设备使用同一仓库、分支和子目录，并升级到支持增量日志的版本。

日志存储在 `子目录/sync/v1/delta-v2/`。超过 512 KiB 的日志自动分片，原始分片为 256 KiB，附带长度和 SHA-256 校验；所有片完整上传后才发布该次提交。不需要 Git LFS。中文和 emoji 按字节重组，不受分片边界影响。

分片解决单文件大小限制，但不能绕过网络、权限和 GitHub 配额。失败的编辑会保留，不会显示为已成功上传。书籍文件、导出和离线缓存包仍走独立的 WebDAV 文件功能。

## 升级说明

首次升级按旧协议读取已有云端数据、建立本机基线，首次写入新日志还会建立一次历史基线；此后只同步新增变更。新安装设备需要读取已提交历史。旧文件保留，不会自动删除。

请同时升级其他设备。切换到新日志后，旧版继续写入旧目录的修改不会被新协议自动接收，不建议新旧客户端混用。

Token 仅保存在本机。同步内容没有额外加密，不要使用公开仓库存放私人阅读记录或敏感规则。

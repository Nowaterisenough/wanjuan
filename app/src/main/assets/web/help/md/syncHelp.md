# 同步

同步用于多设备合并书架、书籍信息、阅读进度、书架分组、书籍分组、书源、订阅及排序，不再提供整包备份和恢复。

## 触发时机

- 应用启动、网络恢复、书架下拉更新和阅读进度变化时同步。
- 书源新增、编辑、删除和排序变化后自动推送本机变更，不反复扫描云端。
- 书籍新增、移出书架、换源、书架分组和书籍分组归属变化后自动推送本机变更。
- 连续批量修改会合并执行；离线或失败的变更保留，联网后重试。
- 设置页的“立即同步”可用于验证配置。

## 增量与进度

启动、联网、下拉更新和立即同步会检查云端版本索引，只下载发生变化的对象。未变化的对象复用按服务器隔离的本地内容缓存；缓存损坏或缺失会重新下载，不会凭空跳过。首次同步、更换服务器、清理缓存后需要建立基线，耗时会更长。

GitHub 使用一次仓库树索引中的文件 SHA 比较版本。WebDAV 每个对象目录只查询一次，并使用 ETag 判断是否变化；如果服务器不提供可靠的 ETag，会保守读取对象，不能只凭粗粒度修改时间判断没变。元数据目录查询不等于重新传输整本书或全部书源。

书架状态和同步设置页会显示连接、检查索引、核对增量、应用数据和上传变更的进度，包括已处理/总数、实际下载对象数、缓存复用数、上传处理数和失败数。下载数按对象统计，不是 HTTP 请求数；冲突合并、重试和索引请求另有网络开销。

## WebDAV

填写服务器地址、账号、密码和子目录。默认保留原有 WebDAV 配置及 `子目录/sync/v1/` 对象格式。

## GitHub 仓库

1. 创建专用的私有仓库，可以是空仓库。
2. 创建 Fine-grained Personal Access Token，仅授权此仓库，并授予 Contents: Read and write 权限。
3. 在同步设置选择 GitHub 仓库，填写 `所有者/仓库名` 和 Token。
4. 分支留空使用仓库默认分支；非空仓库如指定分支，请先创建该分支。
5. 所有设备使用相同的仓库、分支和子目录，点击“立即同步”。

对象写入 `子目录/sync/v1/`，不同设备使用相同的合并协议。更新书籍时通过文件 SHA 检测并重试并发冲突。切换服务器会重新对齐同步状态，不删除本机书籍和规则，也不会删除原服务器上的文件。

同步数据不是加密备份。不要使用公开仓库存放私人阅读记录或敏感规则。Token 只保存在本机，不会作为同步对象上传。GitHub 有 API 速率与文件大小限制，限流、权限不足或冲突时会提示失败，待同步变更不会因此丢弃。单个 JSON 文件需小于 1 MB；仓库树索引若被 GitHub 截断，会报错而非把不完整清单当作同步完成。

书籍文件、书籍导出和离线缓存包仍是独立的 WebDAV 文件功能，不写入 GitHub 仓库。

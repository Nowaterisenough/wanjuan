# 统一字段增量同步（协议 v2）

## 触发与职责

- 书籍、用户分组、书源、RSS 源和订阅规则共用 Room 变更观察、字段差异计算、持久待同步状态和同一个增量引擎。
- 新增、删除、资料修改、分组归属、排序、阅读配置、书籍变量、章节目录和阅读位置变化稳定 1 秒后捕获。没有业务差异时不上传，也不为自动上传发起网络请求。
- 启动、默认网络可用、书架下拉和手动同步只请求增量拉取。既有未完成的本地编辑在拉取成功后由变更上传路径重试，不再由这些入口重新上传全库。
- 下拉仍负责访问书源更新目录，但目录检查和上传不等价；只有实际目录字段变化才进入同一增量队列。收尾调用只补捕获，并在无变化时返回。
- 阅读页面不再在打开、暂停、网络回调和五分钟计时器中单独访问书籍云端文件。阅读保存写入 Room，和其他编辑共用捕获流程。手动进度操作也通过统一引擎。

## 字段差异

每个服务器/对象保留云端基线、上次观察到的本地内容、待发送内容及稳定操作 ID。只有本地内容相对观察值有变化，才更新待发送项；往返编辑回到云端值会取消待发送项。

- 新增发送新对象；修改发送变化字段路径的 set/remove 补丁；删除发送显式删除事件。
- 嵌套配置和规则递归按字段比较，空值和字段移除可区分。数组作为一个字段更新，排序采用三方合并，保留并发新增并尊重删除。
- 章节、页内位置和标题组成原子进度值，避免跨设备拼出无效的“章节＋位置”。进度版本使用提交游标；同位置重复保存的时间戳不算新编辑。
- 本机检查时间、最后打开时间、新章节提示计数、目录请求错误标记、规则请求耗时和轮询更新时间不属于业务修改。
- `lastCheckTime`、`durChapterTime`、`syncTime`、`lastCheckCount` 和更新错误位不会单独触发上传。未初始化和默认阅读配置按同一值比较。实际最新章节、章节数、阅读位置、标签和规则仍同步。
- 书架成员删除仍通过明确的删除操作或移出书架标志判断；不会把缓存清理造成的缺失书籍自动广播为删除。

## 云端提交时间戳与增量拉取

日志位于原服务器根目录下的 `sync/v1/delta-v2/`，旧 `sync/v1/books/` 等目录仅用于迁移。

1. `head.json` 只保存协议号、已发布块的位置和提交时间戳，不增长为整库索引。
2. 每个不可变日志块引用前一块。时间戳为 `max(当前时间, 前一提交时间戳 + 1)`，并通过 GitHub SHA / WebDAV 强 ETag 条件写入发布 head。
3. 并发失败的写入重新读取 head 并合并，不覆盖另一设备已经提交的记录。时间戳是云端提交顺序游标，不依赖不同手机时钟完全一致。
4. 拉取读取 head，只下载本机已保存游标之后的块，按提交顺序应用。不重新枚举整库目录，也不下载已应用的旧对象。
5. 每块的对象应用、云端基线更新、本地待发送项重建和游标推进在同一个 Room 事务内完成。失败或中断不推进未应用块的游标。
6. 上传期间发生的新本地编辑拥有新的操作 ID，旧回执不能清除它。服务器已提交但客户端丢失回执时，下次拉取按操作 ID 确认，避免重复发布。
7. 删除优先于尚未提交的旧编辑；明确重新加入仍可创建新对象。不同字段的并发编辑合并，同字段以成功发布的顺序解决。

已发送但尚未确认的操作单独持久化。上传途中撤销回原值也会保留为后续补偿变更，不会被旧回执吞掉。存在待发送项的失败在应用存活期间按 5 秒至 5 分钟指数退避重试；关闭同步或更换目标后不继续重试原目标。

游标和基线存储在数据库的 `sync_delta_cursor` / `sync_delta_state`，按服务器身份隔离，不依赖可清理的 HTTP 缓存。远端回退、删除日志、损坏或缺少日志块会报错，不把未知状态当作同步完成。

数据库 97 将超过 32 KiB 的同步 JSON 存入 `sync_delta_blob` 的 64 KiB 字节分片，状态行仅保留带校验的引用，避免多份大 JSON 超过 Android CursorWindow 的单行限制。96→97 升级逐列分段读取旧大行，保留游标、待发送和在途操作；不需要清除应用数据。分片与引用在同一事务保存，无引用的旧片会回收。

日常上传复用本轮拉取取得的游标及条件写版本，不重复读取 head。GitHub 不可变日志和分片先尝试创建，仅在冲突时读取并核对内容；相同路径内容不一致时失败，绝不覆盖。已初始化、无远端变更及冲突的单日志块上传只需一次 GET head、一次 PUT block 和一次条件 PUT head。待上传数量与书籍 ID 使用轻量查询，仅解码当前批次的待发送状态；批次大小按实际字段补丁字节数计算。

界面分别记录补丁准备、日志上传、云端提交和本地确认耗时。书架下拉刷新只显示顶部整体进度；后台单书变更在封面以灰度及自上而下恢复彩色表示待上传、数据写入和云端确认阶段（不是字节百分比）。仅在本地确认对应操作且无新待发送修改后完全恢复，失败保留提示，重试继续使用持久化队列。列表和网格使用相同封面反馈，滚动复用不继承其他书籍的状态。

## GitHub 大对象分片

不使用 LFS，不要求另建服务或额外认证。

- 普通日志文件上限 512 KiB；大日志按原始字节切成 256 KiB 分片，分片内使用 Base64，单个上传文件仍小于 512 KiB。
- 分片按 SHA-256 寻址；清单记录总长度、完整哈希及分片顺序。先完整上传分片和日志块，最后条件发布 head。
- 缺片、错误长度和哈希不符都中止应用，不推进游标。失败遗留的未引用分片不会出现在已提交变更中，可以在后续专门的安全回收中处理。
- 中文和 emoji 在完整字节流重组后解码，不会因为分片边界破坏 UTF-8。
- 旧 GitHub 大文件迁移通过 Git Blob API 读取，避免 Contents 的大文件内联 Base64 限制。新日志不依赖目录列举的 1000 项上限。
- 分片解决单文件大小问题，不绕过权限、网络故障、GitHub 配额或仓库总量限制；失败保留本机待发送项。

## 迁移与边界

数据库按 95→96→97 执行非破坏迁移，保留旧同步队列、增量游标和待发送操作。每个目标首次进入 v2 时只读导入旧数据，并使用旧版本规则处理历史冲突和删除。首次发布 v2 日志时建立一次可分片的历史基线，此后只发布增量。首次安装/迁移仍需下载已有历史以建立本机基线。

旧数据迁移只读取一次索引和对象正文：旧冲突处理和新基线复用同一次解析结果，不再二次串行下载。按远端 SHA/ETag 保留可验证的内容缓存，中断后重试复用未变化对象；任何迁移错误仍阻止推进完成标志。界面分别显示增量游标、旧数据清单、迁移读取和基线应用，并展示处理数量与耗时。同步日志记录协议和应用版本、游标、迁移状态、上传/下载/待发送计数，不记录认证信息。

所有参与同步的设备应升级到 v2。切换后旧客户端对旧目录的修改不会自动进入新日志；不要混用旧、新客户端继续编辑。旧文件不删除，便于审计和恢复。

WebDAV 必须支持强 ETag 和条件写入；没有可靠版本标识时明确失败，不降级为可能丢失并发编辑的无条件覆盖。日志当前保留全部已提交历史；首次同步随历史增长，后续拉取只取游标后的记录。压缩历史和删除孤立块需要独立、可验证的回收流程，本版本不做不安全清理。

书籍正文文件、导出和离线缓存包不属于对象同步，仍使用原有 WebDAV 文件功能。

## 验证

- 无变化自动捕获零上传；再次拉取只读 head。
- 多书架仅一书修改时只发送该书的变化字段；进度、分组、源、RSS 和订阅使用同一流水线。
- 两设备不同字段并发、排序新增/删除、时钟偏差、CAS 冲突、提交回执丢失、上传期间编辑、离线重试和事务失败。
- 超过 1 MiB 的中文/emoji 数据经 GitHub API 测试服务分片往返，所有文件小于限制；缺片和失败分片不发布 head、不推进游标。
- Room 95→96 迁移保留旧队列；重建引擎后继续使用已持久化的游标。
